# Ролик 9:16 «Wildberries задерживает выплаты?» (28 августа)

Вертикальное видео для Reels / TikTok / Shorts: **1080×1920, 60 fps, H.264 + AAC, 35,2 c.**
Вся графика синтезируется кодом — ни стоковых клипов, ни логотипов: только векторная
motion-графика на `<canvas>`. Звук — дикторская озвучка поверх процедурной подложки,
которая тоже написана кодом, поэтому сторонней музыки в ролике нет.

Хронометраж задаётся озвучкой: границы сцен поставлены в паузы между фразами,
чтобы кадр менялся на вдохе, а не посреди слова.

```
video/
├── index.html        сцена рендера (холст 1080×1920 + подключение шрифтов)
├── src/
│   ├── util.js       математика, easing-функции, детерминированный шум, типографика
│   ├── fx.js         фон, виньетка, зерно, glitch/RGB-split, motion blur, bloom
│   ├── widgets.js    векторные иконки, карточки, чипы, графики, монеты, разряды таймера
│   ├── scenes.js     семь сцен ролика
│   └── main.js       таймлайн, переходы, покадровый рендер
├── fonts/            Inter + JetBrains Mono (переменные TTF, полная кириллица, OFL)
├── render.mjs        Playwright → покадровый захват → поток в ffmpeg (кадры не пишутся на диск)
├── audio.py          процедурная подложка (суб-бас, удары, whoosh, тики, ризер, пэд)
├── mix.sh            сведение озвучки с подложкой: sidechain-приглушение, -14 LUFS
├── assets/           дикторская озвучка (voiceover.mp3) — задаёт хронометраж ролика
└── build.sh          полная сборка
```

## Сборка

```bash
cd video
./build.sh                       # → out/wildberries_payout_delay_9x16.mp4
./build.sh --preview 3.5,20.5    # только PNG-кадры указанных секунд
VO=path/to/voice.mp3 ./build.sh  # своя озвучка вместо assets/voiceover.mp3
```

Без файла озвучки сборка проходит так же — в ролик уходит одна подложка.

Нужны `node` с пакетом `playwright` (Chromium), `python3` и `ffmpeg`
(если системного нет — берётся бинарник из `pip install imageio-ffmpeg`).
Рендер полностью детерминирован: любой кадр восстанавливается по времени `t`,
случайности заданы фиксированными сидами.

### Двойное время сцен

Сцена получает два времени: **сценарное** (на нём свёрстаны все появления и раскрытия)
и **экранное** (реальное время в ролике). Связывает их карта `anchors` в `main.js` —
пары «сценарное → экранное». «Боевая» часть сцены играет 1:1 и не теряет резкости,
а лишние секунды под длинную фразу уходят в удержание: сценарное время замирает,
но фон, искры, пульсации, орбиты и глитчи продолжают идти в реальном темпе,
поэтому кадр не выглядит стоп-кадром. Так же решается и обратная задача —
сцену можно поджать, ускорив только её хвост.

Переходы на стыках: glitch-склейка (2 c), whip-pan влево (5 c), zoom-punch (9 c),
раскрытие створками (13 c), вертикальный whip (17 c), glitch со вспышкой (21 c).
Каждый переход смещён за стык, чтобы уходящая сцена была уже собрана,
а входящая успевала начать анимацию под смазом.

## Формулировки

Ролик не утверждает причин и не приводит непроверенных данных. Используются только
осторожные конструкции: «продавцы **сообщают** о задержках», «статус: **ожидание**»,
«**что происходит** с выплатой?», «точное время **неизвестно**», а ключевые тезисы
поданы вопросом. Цифры на графиках — абстрактная иллюстрация динамики, без привязки
к конкретным суммам и метрикам.

## Технические параметры экспорта

* 1080×1920 (9:16), 60 fps, прогрессивная развёртка
* H.264 High\@4.2, CRF 19 + `tune=animation`, `aq-mode=3`, `yuv420p`, BT.709, `+faststart`
* AAC 160 kbps, 44.1 kHz, стерео; общий уровень −14 LUFS, true peak −1,5 dBFS
  (норма Reels/TikTok — громче площадка всё равно прижмёт)
* итоговый вес ~13 МБ при 25 c — вчетверо меньше визуально идентичного CRF 16
  (PSNR 48,9 дБ), потому что `tune=animation` не тратит битрейт на плёночное зерно
* безопасные поля: ключевой текст удерживается в диапазоне ~220–1600 px по вертикали,
  чтобы не попадать под интерфейс TikTok/Reels

## Звук

`audio.py` синтезирует подложку: суб-бас, меняющий высоту по сценам, удары и whoosh
на стыках, тиканье с замедлением под сценой таймера, ризер и финальный пэд. Акценты
стоят в тех же точках, что и события в кадре: глитчи хука, красная линия на дате,
затор монет, выезд вопроса, замирание таймера, появление CTA.

`mix.sh` сводит это с озвучкой: голос чистится фильтром 95 Гц и лёгкой компрессией,
подложка приглушается под голосом через sidechain на 4–8 дБ (в паузах звучит в полную
силу), сумма приводится к −14 LUFS.

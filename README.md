# :bar_chart: Wildberries — анализ юнит-экономики

Streamlit-приложение для анализа выгрузок из личного кабинета продавца Wildberries.
Загрузите отчёт (CSV/Excel), сопоставьте колонки, впишите себестоимость — приложение
посчитает выручку, издержки маркетплейса (комиссия, логистика, хранение, штрафы),
валовую прибыль, маржинальность и ROI по каждому артикулу.

### Как запустить локально

1. Установите зависимости

   ```
   $ pip install -r requirements.txt
   ```

2. Запустите приложение

   ```
   $ streamlit run streamlit_app.py
   ```

3. Загрузите файл отчёта WB (плоская таблица с заголовками в первой строке) и
   проверьте автоматически определённые колонки.

## Частотность запросов (WB / Ozon / Яндекс / Google)

Отдельное приложение `search_frequency_app.py`: вводите любой запрос
(«ароматизатор в машину», «магнитный держатель») и сразу видите, сколько раз
его ищут в месяц на четырёх площадках. **Ключи не нужны.**

```bash
pip install -r requirements.txt
streamlit run search_frequency_app.py
```

### Как считается без ключей

Основа — Google Trends: публичный, без токенов и регистрации. Он даёт
относительный интерес, а абсолютные показы получаются калибровкой — запрос
сравнивается с опорным словом, месячная частотность которого известна заранее
(таблица опор в `frequency/trends.py`, код сам подбирает опору подходящего
масштаба).

| Источник | Что складывается в оценку |
|---|---|
| Яндекс | калиброванный замер Trends по России |
| Wildberries | товары в публичной выдаче WB + доля веб-спроса, доходящая до площадки |
| Ozon | товары в публичной выдаче Ozon + та же доля спроса |
| Google | доля Google в поиске РФ от базового замера |

Если Trends ограничит частоту обращений, спрос восстанавливается обратным
ходом по выдаче WB и Ozon — цифры остаются на месте. Коэффициенты модели
вынесены в `frequency/estimate.py`.

### Деплой на Streamlit Cloud

1. Откройте [share.streamlit.io](https://share.streamlit.io) и войдите через GitHub.
2. **Create app → Deploy a public app from GitHub** и заполните:
   - Repository: `ibri95989-hash/cyber_unit_economy_app.py`
   - Branch: `claude/search-frequency-aggregator-li8h4z` (или `main`, если вольёте ветку)
   - Main file path: `search_frequency_app.py`
3. **Deploy.** Зависимости ставятся из `requirements.txt` автоматически.
4. Необязательно: **Settings → Secrets** — вставьте содержимое
   `.streamlit/secrets.toml.example` со своими значениями, чтобы прокси и ключи
   подставлялись сами и их не пришлось вводить в каждой сессии.

Важно про облако: серверы Streamlit Cloud находятся за пределами РФ, и
Wildberries с Ozon нередко не отвечают на запросы из дата-центров. Приложение
это переживёт — оценка достроится по Google Trends, — но если нужны и цифры
маркетплейсов, пропишите в секретах `proxy` с российским адресом.

### Запуск в Docker

```bash
docker build -t frequency-app .
docker run --rm -p 8501:8501 frequency-app
```

Приложение открывается на http://localhost:8501. Полезные варианты запуска:

```bash
# свой порт (Render, Cloud Run и Heroku подставляют PORT сами)
docker run --rm -e PORT=8080 -p 8080:8080 frequency-app

# прокси и ключи без ввода в интерфейсе
docker run --rm -p 8501:8501 \
  -v "$PWD/.streamlit/secrets.toml:/app/.streamlit/secrets.toml:ro" frequency-app
```

Контейнер работает не из-под root и отдаёт healthcheck по `/healthz`, так что
годится для Render, Cloud Run и Kubernetes без доработок.

### Работа через прокси

Если WB, Ozon или Google Trends не открываются напрямую (корпоративная сеть,
блокировки, VPN), укажите прокси — он применяется сразу ко всем источникам.

- **В интерфейсе:** боковая панель → «Сеть» → адрес прокси → «Проверить
  соединение». Поддерживаются `http://`, `https://` и `socks5://`, в том числе
  с логином и паролем: `http://user:pass@host:port`.
- **Из окружения:** галочка «Использовать системный прокси» подхватывает
  `HTTPS_PROXY` / `HTTP_PROXY`, если поле пустое.
- **В CLI:** `python check_sources.py --proxy socks5://127.0.0.1:1080 "запрос"`
  (`--no-system-proxy` — игнорировать переменные окружения).

Для схемы `socks5://` нужен пакет `requests[socks]`, он уже в
`requirements.txt`.

### Проверка источников из терминала

```bash
python check_sources.py "ароматизатор в машину"
```

Печатает ответ каждого источника и сразу показывает, доступны ли с этой машины
Google Trends, WB и Ozon (код возврата 1, если не ответил никто).

### Ключи (по желанию, для точных цифр)

| Источник | Реальные данные | Что нужно |
|---|---|---|
| Яндекс | Wordstat API или XMLRiver | OAuth-токен Вордстата / user+key XMLRiver |
| Wildberries | отчёт «Поисковые запросы» | токен продавца с правом «Аналитика» |
| Ozon | статистика фраз Performance API | Client Id + Client Secret |

Ключи вводятся в боковой панели и нигде не сохраняются. Карточки с точными
данными помечаются зелёным бейджем, оценки — жёлтым.

## Управление кабинетом Ozon через API (пакет `ozon/`)

Модуль даёт Claude (и вам из терминала) прямой доступ к кабинету: остатки,
поставки FBO, рекламные кампании, ставки и статистика продвижения. Работает
на вашей машине, без сторонних сервисов-посредников.

### Самый простой способ: панель в браузере

**Windows, с нуля и без командной строки** — пошаговая инструкция в
[WINDOWS.md](WINDOWS.md): поставить Python, скачать проект, двойной клик по
`start_ozon.bat`, вставить ключи в форму.

Если терминал не пугает — то же самое двумя командами:

```bash
pip install -r requirements-ozon.txt
streamlit run ozon_app.py
```

Откроется страница в браузере. Слева вставьте ключи и нажмите «Сохранить» —
они запишутся в файл `.env` рядом с приложением, больше вводить их не нужно.
Дальше четыре вкладки: **Поставки** (заявки, состав, свободные интервалы
приёмки), **Остатки** (по складам FBO), **Реклама** (кампании и поисковые
фразы), **Ставки** (текущие ставки и их изменение).

Менять кабинет панель по умолчанию не может: тумблер «Разрешить менять
кабинет» выключен, кнопка «Отправить в Ozon» недоступна, а «Посмотреть, что
изменится» показывает таблицу «было → станет» и ничего не отправляет. Там же
задаются потолок ставки и максимальный шаг — страховка от опечатки в цифре.

Запускайте панель на своём компьютере. Выкладывать её на Streamlit Cloud или
любой публичный хостинг не нужно: там форма с ключами окажется доступна посторонним.

### Ключей два, и они разные

| Что | Где создаётся | Переменные |
|---|---|---|
| Seller API — товары, остатки, отправления, поставки | ЛК продавца → Настройки → Seller API → Сгенерировать ключ | `OZON_CLIENT_ID`, `OZON_API_KEY` |
| Performance API — кампании, ставки, статистика рекламы | Рекламный кабинет → Реклама → API-ключи | `OZON_PERF_CLIENT_ID`, `OZON_PERF_CLIENT_SECRET` |

Ключ Seller API создаётся с ролью: «Аналитик» даёт только чтение, «Админ» —
чтение и запись. Роль — самый надёжный ограничитель: ключом с ролью аналитика
поставку изменить нельзя в принципе.

### Настройка без панели, из терминала

```bash
cp .env.example .env      # заполнить своими ключами, файл не попадает в git
pip install -r requirements-ozon.txt
python -m ozon.cli check  # ключи на месте и приняты Ozon?
```

Ключи можно держать и в переменных окружения, и в `.streamlit/secrets.toml`
(`ozon_client_id`, `ozon_api_key`, `ozon_perf_client_id`, `ozon_perf_client_secret`) —
код ищет во всех трёх местах. Никуда, кроме api-seller.ozon.ru и
api-performance.ozon.ru, они не уходят, а в выводе всегда маскируются.

### Предохранитель на изменения

Чтение доступно сразу. Всё, что меняет кабинет — ставки, бюджеты, поставки, —
проходит два барьера:

1. `--apply` в команде (без него идёт сухой прогон: видно, что будет сделано);
2. `OZON_ALLOW_WRITES=1` в окружении.

Плюс потолки `OZON_MAX_BID`, `OZON_MAX_BID_CHANGE_PCT`, `OZON_MAX_DAILY_BUDGET`:
ставка выше потолка или скачок больше разрешённого не пройдут, даже если запись
разрешена. Каждая попытка записи — строка в `ozon_audit.jsonl`.

### Команды в терминале

```bash
python -m ozon.cli supplies                 # заявки на поставку
python -m ozon.cli supply 123456            # состав и статус заявки
python -m ozon.cli timeslots 123456         # свободные интервалы приёмки
python -m ozon.cli stocks --warehouses      # остатки по складам FBO
python -m ozon.cli analytics --date-from 2026-08-01
python -m ozon.cli campaigns                # рекламные кампании
python -m ozon.cli bids 987654              # товары и текущие ставки
python -m ozon.cli stats 987654             # отчёт по кампании
python -m ozon.cli phrases                  # показы и расход по фразам

python -m ozon.cli set-bid 987654 --sku 111 --bid 35          # покажет и остановится
python -m ozon.cli set-bid 987654 --sku 111 --bid 35 --apply  # отправит в Ozon
```

Метода нет в обёртках — есть общий вызов:

```bash
python -m ozon.cli raw seller POST /v1/warehouse/list --body '{}'
```

### Сколько доступа давать

Доступ делится на три ступени, и переключаются они независимо.

| Ступень | Что настраивается | Что можно |
|---|---|---|
| Только смотреть | ключ Seller API с ролью «Аналитик» | остатки, поставки, кампании, отчёты |
| Обратимые изменения | `OZON_ALLOW_WRITES=1` | ставки, включение и выключение кампаний |
| Необратимые действия | плюс `confirm=true` в вызове | создать или отменить поставку, перенести приёмку, поменять бюджет |

Список действий из третьей ступени задаётся переменной `OZON_CONFIRM_ACTIONS`
(по умолчанию — создание и отмена поставки, перенос слота, дневной бюджет).

Настоящая граница — первые две строки: роль ключа проверяет Ozon на своей
стороне, а `OZON_ALLOW_WRITES` читается из окружения, которое задаёте вы.
Третья ступень устроена иначе: `confirm` передаёт тот, кто вызывает метод. Она
защищает от случайного вызова и заставляет проговорить, что именно создаётся,
но не заменяет первые две. Хотите жёсткий запрет на изменения — не включайте
`OZON_ALLOW_WRITES` или выпустите ключ с ролью «Аналитик».

Каждая попытка изменения пишется в `ozon_audit.jsonl`: время, действие,
параметры и отправлено ли оно в Ozon.

### Создание поставки целиком

Одной команды «создай поставку» в API нет: сначала черновик, по нему Ozon
считает доступные склады, затем выбирается интервал приёмки, и только потом
появляется заявка. Цепочка собрана в `ozon/workflows.py`:

```bash
# Шаг 1 — черновик. Ничего не едет и денег не стоит.
python -m ozon.cli new-supply --sku 123456789:10 --sku 987654321:5

# Шаг 2 — заявка, после того как посмотрели склады и интервалы.
python -m ozon.cli new-supply --sku 123456789:10 --warehouse-id 42 --confirm
```

То же самое в панели — вкладка «Новая поставка»: вписать позиции, нажать
«Посчитать черновик», выбрать склад и интервал, поставить галочку
«Проверил состав» и создать заявку.

### Подключение к Claude

Чтобы Claude работал с кабинетом сам, а не через копипасту, поднимите
MCP-сервер — он живёт в этом же репозитории:

```bash
claude mcp add ozon -- python -m ozon.mcp_server
```

После этого у Claude появляются инструменты `ozon_supply_orders`,
`ozon_campaigns`, `ozon_campaign_bids`, `ozon_ad_statistics`, `ozon_set_bid`,
`ozon_plan_supply`, `ozon_create_supply` и другие. Ключи остаются в вашем
окружении: сервер запускается локально, в переписку попадают только ответы Ozon.

Работает это по вашей команде в диалоге: «посмотри остатки и собери поставку на
Хоругвино» — Claude соберёт черновик, покажет склады и интервалы и остановится
перед созданием заявки. Сам по себе, пока вы молчите, он ничего не делает: между
вашими сообщениями сервер просто ждёт. Регулярные проверки без вашего участия —
это уже расписание (cron, планировщик задач), которое запускает
`python -m ozon.cli ...` по времени.

### Что API не умеет

Ставки правятся в кампаниях с ручным управлением. Если у кампании включена
автостратегия, Ozon сам распоряжается ставкой, и запись через API либо
игнорируется, либо возвращает ошибку — сначала переключите стратегию в кабинете.
Версии методов поставок Ozon периодически меняет (v1 → v2 → v3); клиент
пробует свежую версию и откатывается на предыдущую, но при массовом обновлении
сверяйтесь с [документацией](https://docs.ozon.ru/api/seller).

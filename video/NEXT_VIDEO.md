# Как сделать следующий ролик

Всё, что нужно, лежит в этой папке — заново скачивать и настраивать ничего не
надо. Ниже: что где, что менять и на какие грабли не наступать.

## Быстрый старт

```bash
cd video
./build.sh assets/voice_wb_unit_economy.mp3 build/out.mp4      # полная версия
python3 analyze_audio.py <voice> -o build/audio54.json --target 54.2
node capture.mjs --config build/audio54.json --audio <voice_cut> --out build/short.mp4 \
     --ffmpeg "$FFMPEG" --preset veryfast --crf 19
```

`build.sh` сам поднимает шрифты (`fetch_fonts.py` → `render/fonts.css`),
линкует Playwright и считает тайминги. Всё в `build/` — временное.

## Что менять под новый сценарий

| Задача | Где править |
| --- | --- |
| Текст надписей, порядок сцен | `render/scenes_a.js`, `render/scenes_b.js` |
| Раскадровка (секунды сцен) | `STORYBOARD` в `analyze_audio.py` |
| Типы склеек между сценами | массив `BASE` в `render/main.js` (`punch`/`whipL`/`whipR`/`whipU`/`zoomIn`/`zoomOut`) |
| Цифры юнит-экономики | `GATES`, `COGS`, `PROFIT` в `render/scenes_a.js` — считаются сквозняком по всем сценам |
| Палитра | `C` в `render/engine.js` |

Новая сцена = функция `(ctx, p, lt, gt, A)`: `p` — прогресс 0..1 (по нему бьются
биты), `lt` — секунды от начала сцены (по ним живут частицы), `A` — громкость
голоса в этом кадре. Добавить в `BASE` и в `STORYBOARD` — остальное соберётся.

## Проверять глазами до рендера

```bash
node capture.mjs --stills "2.5,24,53,78"     # PNG в build/stills
node capture.mjs --start 20 --limit 120 ...  # кусок видео
node profile.mjs                             # стоимость примитивов в мс/кадр
```

Один кадр рисуется ~25–40 мс. Если какая-то сцена в `profile.mjs` даёт сотни
миллисекунд — ищите живой blur (см. ниже), а не «тяжёлую графику».

## Грабли производительности (проверено на этом ролике)

1. **`ctx.filter = 'blur(...)'` на каждом глифе** — Chromium заводит слой
   размером с холст на КАЖДЫЙ символ: сцена финала стоила 658 мс/кадр вместо 25.
   Расфокус делается тремя смещёнными копиями глифа (`kinetic()` в `engine.js`).
2. **Живой blur у подложек** — только через `plate()`: блюр считается один раз
   и кешируется.
3. **`shadowBlur` большого радиуса на больших фигурах** — заменено спрайтами
   (`glow()`, `dot()`, `streakSprite()`), они кешируются по цвету.
4. **`measureText` в цикле** — `fitSize()`/`layout()` кешируют метрики; без
   этого каждый кадр пересчитывает ширину каждой буквы.
5. **Кодек**: `-preset slow` на 1080×1920@60 даёт ~1 кадр/с на 4 ядрах и
   становится узким местом. `veryfast --crf 19` — ~10 кадр/с, ролик 104 с
   собирается за ~11 минут.

## Синхронизация с голосом

Сейчас склейки подтягиваются к паузам (`silencedetect`), а раскадровка
масштабируется под длину дорожки. Чтобы надписи попадали ровно в фразы, нужны
пословные таймкоды: `transcribe.py` (faster-whisper). В этой сессии модель
скачать не удалось — egress-политика закрывает HuggingFace, openaipublic и
download.pytorch.org. Запасной путь: взять текст озвучки и разложить фразы по
речевым фрагментам пропорционально числу символов.

## Доставка

- Вложение в чат — не больше **30 МиБ**: делайте превью
  (`hqdn3d=1.5:1.5:6:6,fps=30`, `-b:v 1900k` для 104 с ≈ 25 МиБ).
- Для соцсетей — `-crf 23 -maxrate 12M` при 60 fps (~8.7 Мбит/с).
- Мастер 24 Мбит/с (~300 МБ) в репозиторий не кладём: GitHub режет файлы
  больше 100 МБ, и история распухает навсегда.

## Что уже лежит в репозитории

- `assets/voice_wb_unit_economy.mp3` — озвучка этого ролика (можно пересобрать

контейнере сессии.

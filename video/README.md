# Reel renderer — «Считай не выручку, считай прибыль»

Вертикальный ролик 1080×1920 (9:16) о юнит-экономике на маркетплейсе: выручка
растёт, а прибыль съедается комиссией, логистикой, хранением, рекламой,
скидками, возвратами и налогами.

Ролик собирается кодом, а не монтажной программой: каждый кадр — детерминированная
функция времени, отрисованная в Canvas 2D в headless Chromium и отправленная в
ffmpeg. Один и тот же вход всегда даёт один и тот же кадр, поэтому правки
безопасно вносить точечно и перерендеривать.

## Как собрать

```bash
./build.sh path/to/voice.mp3 build/out.mp4
```

Скрипт сам:

1. `fetch_fonts.py` — скачивает кириллические сабсеты Montserrat/Inter и
   инлайнит их в `render/fonts.css` (рендер работает офлайн, знак ₽ приходит из
   сабсета latin-ext);
2. `analyze_audio.py` — считает длительность озвучки, огибающую громкости
   (60 значений в секунду, ей «дышат» свечения) и раскладку сцен: тайминги
   раскадровки масштабируются под реальную длину дорожки, а каждая склейка
   подтягивается к ближайшей паузе между фразами;
3. `capture.mjs` — рендерит кадры в Chromium и стримит их в ffmpeg
   (H.264 high, CRF 17, yuv420p, AAC 192 kbps, faststart).

Полезные флаги:

```bash
node capture.mjs --stills "2.5,24,53"     # PNG-стопкадры в build/stills для проверки
node capture.mjs --start 20 --limit 120   # отрендерить кусок (отладка)
python3 analyze_audio.py voice.mp3 --target 54.2   # уложить визуал в заданную длину
```

## Синхронизация с голосом

По умолчанию тайминги раскадровки масштабируются под длину дорожки, а склейки
подтягиваются к паузам (`analyze_audio.py`). Чтобы надписи попадали в конкретные
фразы, нужны пословные таймкоды:

```bash
python3 transcribe.py build/voice.mp3 -o build/words.json --model small
```

Скрипт использует faster-whisper. В окружении без доступа к HuggingFace модель
не скачается (403 от egress-прокси) — тогда таймкоды берутся из текста озвучки:
паузы уже размечены `silencedetect`, фразы текста раскладываются по речевым
фрагментам пропорционально числу символов, и границы сцен пришиваются к ним.

## Структура

| файл | что делает |
| --- | --- |
| `render/engine.js` | тайминг-функции, easing, кинетическая типографика, фон, зерно, виньетка, спрайты свечений |
| `render/parts.js` | графики, чипы, KPI-плашки, донат, шестерни, спидометр, потоки частиц |
| `render/scenes_a.js` | сцены 1–5: хук, аналитика, обвал прибыли, конвейер расходов, разбор миллиона |
| `render/scenes_b.js` | сцены 6–10: механизм, монтаж «работаешь больше», выручка vs прибыль, финал, CTA |
| `render/main.js` | режиссёр: раскладка сцен по времени и склейки (whip/zoom/punch) |
| `capture.mjs` | Playwright → кадры → ffmpeg |

## Числа в ролике

Все сцены считают одну и ту же юнит-экономику от 1 000 000 ₽ выручки:
закупка 35%, комиссия 17%, реклама 12%, логистика 10%, налоги 6%, скидки 5%,
возвраты 4%, хранение 2% → 90 000 ₽ (9%) чистой прибыли. Проценты живут
в `GATES`/`COGS`/`PROFIT` в `render/scenes_a.js` — меняются в одном месте.
